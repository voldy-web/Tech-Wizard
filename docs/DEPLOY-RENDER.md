# Deploying the backend on Render

The API runs as a **Docker web service** (Render has no native Java runtime) with a **managed PostgreSQL** database.
Everything is described in `render.yaml` at the repo root, so you set it up once with a Blueprint.

## What you need
- The project pushed to a GitHub repository (Render deploys from GitHub).
- A free Render account: https://render.com

## One-time setup

1. **Push the code** (you do the git part).
2. In Render: **New + → Blueprint** → connect GitHub → choose this repository → **Apply**.
   Render reads `render.yaml` and creates:
   - `tech-wizard-db` – PostgreSQL
   - `tech-wizard-api` – the Spring Boot API (built from `backend/Dockerfile`)
3. Wait for the first build (a few minutes). When the service shows **Live**, open
   `https://<your-service>.onrender.com/api/health` – you should see `{"status":"UP"}`.
4. Get the API key: open **tech-wizard-api → Environment**, reveal **API_KEY** and copy it
   (Render generated it for you).
5. Point the mobile app at it – edit `mobile/.env`:
   ```
   EXPO_PUBLIC_USE_MOCK=false
   EXPO_PUBLIC_API_URL=https://<your-service>.onrender.com
   EXPO_PUBLIC_API_KEY=<the API_KEY you copied>
   ```
   then restart Expo with `npx expo start -c`. (The hosted URL works from any network, so the tunnel and LAN IP are not needed.)

Tables are created automatically on first start (`ddl-auto: update`). No sample data is added in production.

## How the pieces connect
| Setting | Where it comes from |
|---|---|
| `SPRING_PROFILES_ACTIVE=postgres` | `render.yaml` / Dockerfile |
| `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD` | filled from the Render database by `render.yaml` |
| `PORT` | injected by Render; the app listens on it |
| `API_KEY` | generated by Render; the app rejects `/api/*` calls without header `X-API-Key` (except `/api/health`) |
| `CORS_ORIGINS` | optional; the native app does not need CORS, only set it for a web front end |

## Good to know
- **Free web services sleep** after a period of inactivity; the first request afterwards can take up to a minute.
  The app waits up to 45 s and the error screen tells you to try again. A paid plan keeps it awake.
- **Free PostgreSQL databases on Render have limits** (historically they expire after a set period and are small).
  Check the current terms on Render's pricing page, and move to a paid database before you rely on the data.
  You can take a backup any time with `pg_dump` using the database's *External Database URL*.
- **The API key protects casual access, not determined attackers.** `EXPO_PUBLIC_*` values are bundled into the app,
  so anyone who unpacks the app can read the key. For real multi-user use, add user login (accounts + tokens) next.
- Logs: **tech-wizard-api → Logs**. Redeploys happen automatically on every push (`autoDeploy: true`).
- Schema changes: `ddl-auto: update` is fine to start; adopt Flyway migrations before making breaking schema changes.

## Run the production setup locally (optional)
```bash
cd backend
./mvnw -DskipTests package
SPRING_PROFILES_ACTIVE=postgres DB_HOST=localhost DB_PORT=5432 DB_NAME=techwizard DB_USER=techwizard DB_PASSWORD=secret \
  API_KEY=dev-key java -jar target/tech-wizard-backend-0.1.0.jar
curl -H "X-API-Key: dev-key" http://localhost:8080/api/dashboard
```
Docker: `docker build -t tech-wizard-api backend && docker run -p 10000:10000 -e PORT=10000 -e DB_HOST=... tech-wizard-api`
